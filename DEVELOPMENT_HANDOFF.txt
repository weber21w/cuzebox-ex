UART FIX: WHAT CHANGED
Production change: cu_avr.c.
Regression changes: tests/bootloader/interrupt_regression.c and a reset
dependency stub in tests/bootloader/resident_bootloader_regression.c.
Documentation: documentation/serial.md, USART transmit-complete scanline timer.

The old usr0_tran/usr0_end scheduler and TX ISR existed, but the UDR write
code that armed the old fixed 1,304-clock timer was commented out. Endpoint
status polling therefore worked while interrupt-driven scanline termination
did not reliably run.

The AVR core now schedules TX completion independently of the ESP/serial peer.
Frame duration follows UBRR, U2X, data bits, parity/stop bits, and synchronous
master/MSPIM framing. Existing saved CPU fields hold the shift deadline;
UDRE distinguishes an occupied one-byte holding register. No CPU-blob layout
change was made. Full/disabled UDR writes are ignored. TXC is a latched event,
not an idle-level flag imported from the peer. It starts clear, acknowledges
on write-one-to-clear or ISR dispatch, and obeys TXCIE/global interrupt masks.
Mask-only writes and TXC acknowledgment avoid reconfiguring/flushing RX.
Watchdog reset cancels the MCU and peer pending transmitter state.

This is a TX-complete timer fix, not a full USART interrupt implementation.
RX and UDRE interrupt vectors, external XCK edges and baud-generator start
phase are not implemented. No browser binary was rebuilt or deployed.

PERFORMANCE RESULT AND LIMITS
Seven alternating old/new Windows runs per case; 115,200,000 emulated clocks
each. Production switch core compiled separately with matched -O3 flags and
no core LTO; same UART/AT and dependency objects. No rendering/audio, physical
serial adapter or live network. GetProcessTimes measures host CPU time.

Idle: unchanged median. ESP AT at ~224 kbaud: +3.28% median CPU time.
Raw serial at ~9,600 baud: unchanged; ~224k and ~1.79M: about 1.5-1.6% lower
medians, treated as approximately unchanged rather than a universal speedup.
Every paired run had identical emulated cycles and transmitted byte counts.
Thus no measured UART bandwidth loss in these synthetic cases; do not turn
the CPU-time result into a whole-app FPS or physical-adapter guarantee.

The initial performance-invalid-harness files are INVALID: setup overwrote
the new core's read-only UDRE flag and it sent no data. Only performance.json
and PERFORMANCE.txt are valid. benchmark_uart.py/uart_perf.c under _obj_ use
Windows APIs and require adaptation before rerunning on Linux.
